⏺ 외우기보단 패턴 이해가 낫다. 한번 잡으면 변형 다 풀림.
  외울 게 아니라 "패턴 4단계"
  def dfs(상태):
      if 종료조건:
           return 성공이면 1 else 0   # 카운트 문제
       return dfs(분기1) + dfs(분기2) + ...

   이 골격만 있음. 문제마다 채우는 건 4개:

  1. 상태(state) = 재귀 인자로 뭘 들고 다닐지
     - 타겟넘버: (idx, total)
     - N-Queen: (row, 놓인_열들)
     - 부분집합: (idx, 현재조합)
  2. 종료조건 = "더 이상 결정할 게 없을 때"
     - 타겟넘버: 숫자 다 씀 idx == len(numbers)
     - 미로: 도착점 도달
  3. 판정 = 종료 시점에 성공/실패 판정 후 값 반환
    - 카운트: 1 or 0
    - 최소값: 지금까지 비용
    - 경로: 경로 리스트
  4. 분기 = 이 시점에서 가능한 선택지 모두 재귀
    - 타겟넘버: +num, -num 두 개
    - 부분집합: 포함, 제외 두 개
    - 미로: 상하좌우 네 개
  연습법
  같은 골격으로 문제 3~5개 풀어봐:
  - 부분집합 합 (백준 1182)
  - 조합/순열 만들기
  - N-Queen
  - 로또의 최고 순위와 최저 순위 아님, 스킵. 대신 → 소수 만들기 (프로그래머스)
  3번째쯤 되면 몸이 기억함. 그게 "외운다"보다 강함.
  함정 하나
  재귀 = 스택. Python 기본 재귀 한도 1000. 깊이 깊어지면:
  import sys
  sys.setrecursionlimit(10**6)
  타겟넘버는 최대 20 깊이라 안 걸림. 백준류에선 자주 걸림.

⏺ 진단 (오늘 코드 기준)
  부족한 3가지:
  1. "함수가 무엇을 반환할지" 먼저 안 정함
    - dfs가 숫자 합인지, 방법 수인지 흔들림
    - 재귀 시작 전에 한 줄로 못 씀: "dfs(...) returns: ___"
    - 이거 안 정하면 종료조건도 못 씀
  2. 상태 설계가 어색함
    - 전역, 인자, 반환값 섞음
    - 원칙: 바뀌는 값은 인자, 결과는 반환. 전역은 금지 (코테 한정)
  3. 베이스 케이스 오프바이원
    - size = len(numbers) - 1, numbers[size-1] → 왜 -1? 감으로 뺌
    - 인덱스 다룰 때 "이 시점에 idx가 뭘 가리키나" 그림 그려 확인 안 함
  연습법 (4주 플랜)
  주 1~2: 패턴 강제 학습
  매 문제 풀기 전 주석 3줄 먼저 씀:
  # state: (idx, total)
  # base: idx == n → total == target 이면 1 else 0
  # branch: +num, -num
  이거 안 쓰면 코드 못 침. 강제. 3주 지나면 습관.
  주 3: 패턴별 5문제씩
  - DFS/백트래킹: 타겟넘버, N-Queen, 부분집합 합, 조합, 순열
  - BFS: 미로 최단거리, 단어 변환, 게임 맵 최단거리
  - DP: 피보나치 → 계단 오르기 → 배낭 → LIS
  - 그리디: 회의실 배정, 동전, 큰수 만들기
  - 투포인터/슬라이딩: 부분합, 연속수열
  패턴당 첫 문제는 답 보고 이해 → 나머지 4문제 혼자.
  주 4: 시간 재고 풀기
  - 프로그래머스 Lv.1~2 각 20분, Lv.3 40분
  - 시간 넘기면 답 보되, 다음 날 다시 혼자 재풀이
  - "봤던 문제인데 못 품" = 이해 안 됨. 반복.
